# V58：周期、反馈、PWA与后台提醒

## 训练计划

新训练使用版本58；有进度的旧草稿继续按原版本解释，避免组号串位。反馈、逐组数值和动态计划快照随草稿同步。历史负重不会重写，也不将双臂划船负重迁移到单臂划船。

| 模块 | 工作组起点 |
|---|---|
| Push | 平板卧推3、上斜卧推3、坐姿推肩2、侧平举3、过顶臂屈伸2 |
| Pull | 下拉3、胸托上斜划船2、单臂划船2、反向飞鸟3、弯举2 |
| 腿＋核心 | 保加利亚分腿蹲2、负重臀桥2、哑铃罗马尼亚硬拉2、卷腹2、平板2、屈膝侧桥2 |

组数按每侧计一次，不乘2。腿部按维持目标控制量；核心不取代营养与体脂管理。每周两轮PPL为目标而非必须六练，篮球和恢复情况允许顺延。上肢胸与背每周约12和14个直接工作组；复合动作不机械重复计为每个参与肌群的有效组。哑铃RDL补齐髋折叠与腿后侧刺激，先学习动作；没有同动作历史时不臆造起始公斤数。

`adaptive.js`依据同动作最近3次记录及一次简短反馈，先增加目标范围内的次数。连续两次全目标工作组达上限、动作质量稳定且余力约2次以上，才建议加0.5kg且不超过5%；器械无此档位就维持，由用户确认。最多每次上肢额外2组、每动作最多4组；仅连续3次轻松达标且不能小幅加重时加组。腿部不自动增组。动作失控或连续两次吃力且未达下限时减少组数/各组自身负重，疼痛时显示暂停提醒。缺少反馈时不自动升级。算法是保守决策规则，不是经过临床验证的AI处方。

依据：ACSM 2026立场文件 https://doi.org/10.1249/MSS.0000000000003897 ，https://acsm.org/resistance-training-guidelines-update-2026/ 。高训练量可利于增肌，但不支持把同一剂量当个人最优值。动作简图与三条提示用于现场回忆，不替代教练观察；NASM/ACE动作库可作进一步学习。

## 周期与AI报告

`cycles.js`按Brisbane日期顺序识别Push→Pull→Legs；篮球/休息不推进，空工作组不推进，新的Push重启未完成周期，未来记录忽略。历史统计直接重算，AI文字保留生成快照；来源版本变化、待上传或冲突显示待更新。

私人表`gym_ai_reports`已部署，owner只读，客户端不能写。最近两轮已实际写入并读回。ChatGPT自动任务每小时检查新完整周期和历史更正，生成分析后按来源版本校验写入，非自然日结算、非App本地伪AI、非即时数据库触发器；运行依赖任务和Supabase连接可用。App下次联网刷新读取，缓存本账号报告用于离线查看。公开仓库不含个人训练记录或用户ID。

## PWA与同步

固定manifest id/scope/start_url，PNG图标及apple-touch-icon。Service Worker整套预缓存成功才激活；导航和静态模块使用同一缓存版本，避免网络先行导致HTML和模块混装。私人API不经过Service Worker缓存。更新提示由用户保存后重开，不在训练中强制刷新。

同设备同入口保留账号会话；首次在主屏幕入口可能仍需登录一次，网页不能跨Safari/独立App存储沙箱强行复制凭据。恢复账号后自动导入该入口的访客记录/有进度草稿，同日期差异保留冲突，一次性标记避免重复导入；不删除访客副本。账号间保持隔离。

## 计时后台提醒

前台使用截止时间计算、提示音和可用时震动。主屏幕Web App内点击启用通知，取得Push订阅后关联当前owner/device；服务端定时队列触发Edge Function发送加密Web Push，暂停/重置取消排队项。定时分发每10秒检查有到期任务才调用，过期2分钟清理、最多3次尝试，410移除失效订阅。

平台JWT验证保持开启，另用Vault worker token限制Cron；VAPID私钥和服务角色密钥只在服务端。前端只读取VAPID公钥。SQL历史005/006和函数源码已入库；不是可重复执行的初始化脚本。iOS需要主屏幕安装、用户手势授权和网络，通知可能延迟或受系统专注模式影响；离线/锁屏准点闹钟不作承诺。依据 https://webkit.org/blog/13878/ 和Apple Web Push文档。
