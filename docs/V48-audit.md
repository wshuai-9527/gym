## 根因和处理

| 区域 | V48 根因 / 风险 | V49 实现 |
|---|---|---|
| 日期 | YEAR=2026、M.D 丢失年份、计划始终最后日期+1，长时间未开可能停在过去 | ISO 日期、Brisbane 日期边界、旧 M.D 明确按 2026 迁移；今日计划与历史日期解耦，活动草稿保持原日期 |
| 自动补休 | 只启动时执行；没有服务器定时器；只检查勾选，不保护已编辑未勾选 | 启动/回前台/分钟检查；编辑草稿保护；删除墓碑不重建；独立 SQL 定时任务提案，默认关闭直到用户开启 |
| 草稿 | 只存在 localStorage；sig 改变时静默重置；导航重画可能丢上下文 | 草稿作为独立文档进入同步队列；切换有进度计划需确认；账户隔离；旧草稿保留 |
| 上传 | 先删 training_sets，再插入；计数 *3 写为一组；忽略删除响应；未登录仍报同步成功 | 旧表只读导入；单文档事务 RPC；保留原组字符串/计数；版本检查、幂等收据、明确待同步状态 |
| 读取 | 直接替换本机；未按账号隔离；分页缺失 | 用户过滤、分页、待上传数据优先保留、冲突显式解决；重复旧日期阻断迁移 |
| 历史 | 删除仅本地，上传会复活；无编辑；手工新增可能覆盖整日 | 整日编辑与删除进入持久队列；删除墓碑；变更日期先创建目标再删除来源；覆盖确认 |
| 分析 | 任意负荷×器械系数×经验肌群权重，称“刺激量”；核心计时为零；篮球计作恢复；未知动作影响 PPL | 近7天原始负荷、组数、计时分列；主项低次数 e1RM；未知动作不推进 PPL；删除刺激评分与恢复预测 |
| 计时 | 每秒减一，后台节流导致误差；重置不停止旧 interval | 持久化结束时间戳、暂停剩余时间、重载恢复 |
| 离线 | 首页注销全部 SW，删除整个 origin 的缓存；SW 从不预缓存 | 作用域内应用壳预缓存；只清理 Gym 缓存；同步失败保留队列、在线/前台/定时重试 |
| 输出安全 | 历史、手工输入、云端错误直接 innerHTML | 用户内容 HTML 转义；错误用 textContent；移除固定邮箱 |

## 科学分析边界

保留动作模板和现有 UI。模块、动作组数与外部负荷是描述性数据，不能当增肌刺激或损伤风险预测。每只器械/每侧输入不擅自换算双侧总量。Epley 仅限主项 1–10 次，同动作同填写规范比较；非接近最大努力的组不能视为真实 1RM。不提供无依据的恢复/ACWR 分数。模板仍为既有 PPL，不声称个性化最优计划。
